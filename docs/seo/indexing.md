# インデックス登録（検出-インデックス未登録）の見方と、サイトマップの lastmod

## Search Console のデータは遅れる
「ページのインデックス登録」の画面は、数日〜1〜2週間遅れる（仕様）。新しい情報が要るときは、次を使う。

| 見る場所 | 遅れ | 分かること |
| --- | --- | --- |
| URL検査（上部の検索欄に URL） | ほぼ即時 | そのページの今の状態、最後にクロールされた日。「公開URLをテスト」で今の状態、「インデックス登録をリクエスト」（1日の回数に上限あり。重要なページから） |
| 設定 → クロール統計情報 | ほぼ毎日 | Google が1日に何ページ読んだか。「未登録」が減る前に、読まれる回数が増えるはず（先行指標） |
| サイトマップ | 数日 | 最後に読み込まれた日、見つかったURLの数 |
| 検索パフォーマンス | 1〜2日 | 表示回数が出ているページは登録済み |
| `site:ground-golf-navi.com` 検索 | 即時 | だいたいの登録数（正確ではない） |

## サイトマップの lastmod（`astro.config.mjs`）
更新日を付けるのは、**検証できる日付があるページだけ**（日付を偽装しない）。
- 記事: フロントマターの `updatedDate`（なければ `pubDate`）
- カテゴリ・トップ: 配下の記事の最も新しい日付
- 都道府県ページ（47）: `data/places/places.json` の取得日と `details.json` の取得日の最も新しいもの（市区町村コードの先頭2桁=JIS都道府県番号）
- 大会カレンダー: `data/events/approved.json` の確認日の最も新しいもの
- 付けない: `/about/`、`/privacy-policy/`、`/affiliate-disclosure/`（日付の元になるデータがない）
- 現在 78ページ中 75ページに付く。データを更新したら（施設データ・イベントの再取得）、日付は自動で新しくなる

## 未登録を減らすためにできること
- 重要なページに「インデックス登録をリクエスト」（ギフトガイド、体験教室、ゲートボールとの違い、打ち方・距離感など）
- 内部リンクを増やす（未登録のページへ、登録済みの関連ページから）
- 薄いページを増やさない

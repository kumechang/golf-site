# 市区町村の施設データ（都道府県ページの「市区町村の案内に、グラウンドゴルフの記載がある施設」）

## 何を載せているか
市区町村が公開している施設の案内ページのうち、「グラウンドゴルフ」の記載があったページへのリンク。載せるのは **市区町村名・施設名・元ページのURL・取得日** だけ。ページの本文・画像・住所・電話・営業時間は載せない（保存もしない）。

- 表示: 各都道府県ページ（`/community/find-a-club-near-you/<県>/`）の `#municipal-places`（`src/components/MunicipalPlaces.astro`）
- データ: `data/places/places.json`（整形後）、`data/places/overrides.json`（運営者の判断）
- 読み込みと検証: `src/data/places.ts`（不正なデータはビルドを失敗させる）
- 調べ方の説明: `/about/#places`

## 元データについて
運営者が、各自治体の1次情報（施設案内ページ）を、取得時に robots.txt と利用規約を確認しながら調べたCSV（1,421行・487市区町村、2026-10-17〜18）。CSV自体は、自治体ページから抜き出した文（`matched_text`）を含むため、**リポジトリには入れない**。

## 更新手順
```
npm run places:clean -- <再調査CSV> --review=<確認用CSV>
```
1. `data/places/places.json` が更新される。確認用CSVに、除外の理由（イベント、http、本文に記載なし など）と、確認用の印（用語の説明の可能性・使えない趣旨の可能性・ゴルフ場の名前・名前が一般的）が出る
2. **印のあるものは載せない**（`places.ts` が黙って除外する）。施設名を通読して、おかしいものは `data/places/overrides.json` で直す
3. `npm run build`（検証・施設名の検査が通ること）→ 通常の手順（コミット → push → PR → squash）

### overrides.json
`source_url` をキーに、次のいずれかを指定する。再生成しても消えない。
```json
{ "overrides": [
  { "source_url": "https://…", "exclude": true },
  { "source_url": "https://…", "name": "直した施設名" },
  { "source_url": "https://…", "as_listing": true }
] }
```
- `exclude`: 載せない（取り下げ依頼が来たときは、これを足して当日中に反映する）
- `name`: 施設名を直す
- `as_listing`: 施設名を捨てて「◯◯市の施設の案内ページ」のリンク扱いに降格する（迷うものはこちらが安全）

## 整形のルール（`scripts/places/lib.mjs`）
- イベント・大会募集・お知らせ・本文に記載なしのページは除外
- http:// のURLは除外（https で開けるか未確認のため）
- 施設名は、リンク文字列（別ウィンドウ等）・日付・担当課名・絵文字を掃除。手続きの名前、文で終わるもの、複数施設の連結などは、一覧ページ扱いに降格
- 同じ市区町村の同じ施設名は1件にまとめる

## 書き方の約束
- 「利用できます」とは書かない（確認できたのは「市区町村の案内に記載がある」まで）
- 「公式」「提供」「施設一覧」「全国の」は使わない。載っていない市区町村は「未確認」であり「ない」ではない
- 件数の多い少ないは調べ方の差。親ページに県別の件数は出さない（ランキングに見えるため）
- 構造化データ（LocalBusiness / Place など）は付けない

## 絞り込み欄
掲載が10件以上の県には、市区町村名・施設名で絞り込む欄が出る（`MunicipalPlaces.astro` 内の小さなスクリプト。JavaScript が使えないときは欄ごと出ない）。ひらがな・カタカナ、全角・半角、大文字・小文字の違いは無視する。入力を消すと元の開閉の状態に戻る。件数がさらに増えたら、親ページに全国を横断する検索を足す（検索用のデータを別に持つ）。

## レビューで分かったこと（2026-10-18）
- 施設名は自動で整えているため、再調査のたびに、施設名の通読が必要（`places-review` の指摘は 664 件中約 63 件が不自然だった）。直したものは `data/places/overrides.json` に入っている
- 一覧ページ（施設名なし）へのリンクは、1つの市区町村につき上位3件まで表示する
- 見出し（h3）は市区町村名。折りたたみ（details）の外に置く（summary の中の見出しは、スクリーンリーダーの見出し一覧に出ない）

## 住所・電話番号（詳細CSV）
運営者が、自治体の1次情報（取得時に robots.txt と規約を確認）から、地域を限って取った施設ごとの住所・電話番号。元CSV（`grandgolf_places_detail_complete*.csv`）はリポジトリに入れない。

```
npm run places:details -- <詳細CSV> --review=<確認用CSV>
```
- `data/places/details.json` に、施設名・住所・電話番号・元ページURL・取得日だけを書く（`matched_text`・`keyword_evidence`・担当課名は使わない）
- 除外: http／施設名として載せられないもの（一覧・見出し・窓口・活動名のみ）／住所が不自然／**住所が別の市区町村から始まるもの**／同じ市区町村・同じ施設名で住所か電話が食い違うもの
- 市区町村名のない住所は、市区町村名を補う（例: 「南田町4-40」→「三島市南田町4-40」）
- 電話が「問い合わせ先の電話」と同じ番号のものには `phone_is_contact` を付け、表示は「問い合わせ先」（施設の電話番号と区別する）
- 表示: `src/data/places.ts` が、同じ市区町村・同じ施設名の施設に住所・電話を足す。なければ住所つきの施設として加える。元ページURLは住所が載っていたページに差し替える
- 出典の表記: 「市区町村のページに記載（取得日）」。同じ施設が「住所・電話番号を個別に確認できた施設の例」の節にもあるときは、そちらを外す（`detailedFacilityKeys`）
- 現在: 476件（電話あり373）・172市区町村。施設名は自動で整えているので、再取得のたびに確認用CSVを通読する

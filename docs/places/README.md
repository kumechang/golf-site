# 市区町村の施設データ（都道府県ページの「市区町村の案内に、グラウンドゴルフの記載がある施設」）

## 何を載せているか
市区町村が公開している施設の案内ページのうち、「グラウンドゴルフ」の記載があったページへのリンク。載せるのは **市区町村名・施設名・元ページのURL・取得日** だけ。ページの本文・画像・住所・電話・営業時間は載せない（保存もしない）。

- 表示: 各都道府県ページ（`/community/find-a-club-near-you/<県>/`）の `#municipal-places`（`src/components/MunicipalPlaces.astro`）
- データ: `data/places/places.json`（整形後）、`data/places/overrides.json`（運営者の判断）
- 読み込みと検証: `src/data/places.ts`（不正なデータはビルドを失敗させる）
- 調べ方の説明: `/about/#places`

## 元データについて
運営者が、各自治体の1次情報（施設案内ページ）を、取得時に robots.txt と利用規約を確認しながら調べたCSV（1,421行・487市区町村、2026-10-17〜18）。CSV自体は、自治体ページから抜き出した文（`matched_text`）を含むため、**リポジトリには入れない**。

## 更新手順
```
npm run places:clean -- <再調査CSV> --review=<確認用CSV>
```
1. `data/places/places.json` が更新される。確認用CSVに、除外の理由（イベント、http、本文に記載なし など）と、確認用の印（用語の説明の可能性・使えない趣旨の可能性・ゴルフ場の名前・名前が一般的）が出る
2. **印のあるものは載せない**（`places.ts` が黙って除外する）。施設名を通読して、おかしいものは `data/places/overrides.json` で直す
3. `npm run build`（検証・施設名の検査が通ること）→ 通常の手順（コミット → push → PR → squash）

### 追加の調査CSVを足すとき（2026-11-05 に実施）
運営者が、あとから見つけた施設ページのCSV（列: prefecture, municipality_code, municipality_name, page_title, page_url, matched_text, found_via, page_kind, facility_like_title, …。`match_count`・`surveyed_at` の列はない）を足すときは、今ある places.json を消さずに足す。
```
node scripts/places/check-https.mjs <追加CSV>          # http のURLが https で開けるか（開けたものだけ data/places/https-upgrades.json に残る）
node scripts/places/clean-places.mjs <追加CSV> --append --surveyed=<CSVの取得日> --review=<確認用CSV>
```
- この形式の `found_via=event` は「イベントのページを調べていて見つけた」の意味なので、イベント扱いで除外せず、`page_kind=facility` のものを施設ページとして読む（`--append` が読み替える）
- すでに載せているもの（同じ元ページ、同じ市区町村の同じ施設名）は足さない
- **メニューなどに出る語を除く**: 同じ市区町村で、同じ抜き出し文が5ページ以上に出るときは、サイドメニューの語の可能性が高いので載せない（海津市・垂水市・岩美町で実際に起きた）
- 追加後に、確認用CSVの「今回追加」の列で施設名を通読し、おかしいものは `overrides.json` に足す（手順の例は下）
- 実績: 320行 → 250件追加（施設112・一覧ページ138、39県）。http の9件は、すべて https で開けたので追加

### overrides.json
`source_url` をキーに、次のいずれかを指定する。再生成しても消えない。
```json
{ "overrides": [
  { "source_url": "https://…", "exclude": true },
  { "source_url": "https://…", "name": "直した施設名" },
  { "source_url": "https://…", "as_listing": true }
] }
```
- `exclude`: 載せない（取り下げ依頼が来たときは、これを足して当日中に反映する）
- `name`: 施設名を直す
- `as_listing`: 施設名を捨てて「◯◯市の施設の案内ページ」のリンク扱いに降格する（迷うものはこちらが安全）

## 整形のルール（`scripts/places/lib.mjs`）
- イベント・大会募集・お知らせ・本文に記載なしのページは除外
- http:// のURLは除外（https で開けるか未確認のため）
- 施設名は、リンク文字列（別ウィンドウ等）・日付・担当課名・絵文字を掃除。手続きの名前、文で終わるもの、複数施設の連結などは、一覧ページ扱いに降格
- 同じ市区町村の同じ施設名は1件にまとめる

## 書き方の約束
- 「利用できます」とは書かない（確認できたのは「市区町村の案内に記載がある」まで）
- 「公式」「提供」「施設一覧」「全国の」は使わない。載っていない市区町村は「未確認」であり「ない」ではない
- 件数の多い少ないは調べ方の差。親ページに県別の件数は出さない（ランキングに見えるため）
- 構造化データ（LocalBusiness / Place など）は付けない

## 絞り込み欄
掲載が10件以上の県には、市区町村名・施設名で絞り込む欄が出る（`MunicipalPlaces.astro` 内の小さなスクリプト。JavaScript が使えないときは欄ごと出ない）。ひらがな・カタカナ、全角・半角、大文字・小文字の違いは無視する。入力を消すと元の開閉の状態に戻る。件数がさらに増えたら、親ページに全国を横断する検索を足す（検索用のデータを別に持つ）。

## レビューで分かったこと（2026-10-18）
- 施設名は自動で整えているため、再調査のたびに、施設名の通読が必要（`places-review` の指摘は 664 件中約 63 件が不自然だった）。直したものは `data/places/overrides.json` に入っている
- 一覧ページ（施設名なし）へのリンクは、1つの市区町村につき上位3件まで表示する
- 見出し（h3）は市区町村名。折りたたみ（details）の外に置く（summary の中の見出しは、スクリーンリーダーの見出し一覧に出ない）

## 住所・電話番号（詳細CSV）
運営者が、自治体の1次情報（取得時に robots.txt と規約を確認）から、地域を限って取った施設ごとの住所・電話番号。元CSV（`grandgolf_places_detail_complete*.csv`）はリポジトリに入れない。

```
npm run places:details -- <詳細CSV> --review=<確認用CSV>
```
- `data/places/details.json` に、施設名・住所・電話番号・元ページURL・取得日だけを書く（`matched_text`・`keyword_evidence`・担当課名は使わない）
- 除外: http／施設名として載せられないもの（一覧・見出し・窓口・活動名のみ）／住所が不自然／**住所が別の市区町村から始まるもの**／同じ市区町村・同じ施設名で住所か電話が食い違うもの
- 市区町村名のない住所は、市区町村名を補う（例: 「南田町4-40」→「三島市南田町4-40」）
- 電話が「問い合わせ先の電話」と同じ番号のものには `phone_is_contact` を付け、表示は「問い合わせ先」（施設の電話番号と区別する）
- 表示: `src/data/places.ts` が、同じ市区町村・同じ施設名の施設に住所・電話を足す。なければ住所つきの施設として加える。元ページURLは住所が載っていたページに差し替える
- 出典の表記: 「市区町村のページに記載（取得日）」。同じ施設が「住所・電話番号を個別に確認できた施設の例」の節にもあるときは、そちらを外す（`detailedFacilityKeys`）
- 現在: 476件（電話あり373）・172市区町村。施設名は自動で整えているので、再取得のたびに確認用CSVを通読する

## 重複の整理（同じ場所の判定）
名前が少し違っても、**住所と電話番号が同じ**なら同じ場所として扱う（`src/data/place-keys.mjs`、テストは `scripts/crawler/tests/place-keys.test.mjs`）。

- 電話番号は、ハイフン・括弧・空白・全角を取り去った**数字だけ**で比べる（「0297-74-2141」と「0297742141」は同じ）
- 住所は、都道府県名・括弧書き・空白を外し、丁目・番地・番・号・「の」・ハイフンの種類・漢数字の違いをそろえて比べる
- **電話番号のない施設はまとめない**（住所が町名までのもの、同じ町名の別の施設があるため）
- 同じ市区町村の施設で一致したものは1件にまとめる。代表は最初の施設で、ほかの名前は「同じ所在地・電話番号の施設：…」として残す（`alsoNames`）
- 「住所・電話番号を個別に確認できた施設の例」の節の施設が、市区町村の施設と住所・電話番号が同じなら、そちらを外す（名前が一致するものも外す）
- まとめない例: 住所は同じで電話が違う施設（別の施設の可能性がある）

## 補完済みの統合CSV（2026-10-20）
運営者が、未記載の住所・電話番号を補った統合CSV（`grandgolf_facilities_merged_enriched.csv`、1,090行）。

```
npm run places:details -- <統合CSV> --enriched --fetched=<ISO日時> --review=<確認用CSV>
```
- 列: 都道府県, 市区町村コード, 市区町村, 施設名, 住所, 電話番号, 問い合わせ先, 問い合わせ電話, 元ページ, 情報補完, 重複統合
- **情報補完の値**: `既存データ`／`未補完`（住所も電話もない行は載せない）／`問い合わせ電話を転記`（電話番号に、問い合わせ先の電話を入れたもの。**施設の電話ではない**ので、「問い合わせ先」として表示する）／`Web補完`（元ページに載っていないものを Web で補ったもの。出典を「Web上の公開情報で補ったもの」と表示し、「市区町村のページに記載」とは書かない）
- 市区町村コードが空の行は、すでにある places.json の（都道府県, 市区町村）から補う
- 住所なし・電話ありの行も載せる（所在地の行を出さない）。同じ施設の行は、片方が空なら補い合い、両方にあって食い違うときだけ載せない
- 今回のCSVに入っていない、すでに載せていた施設は残す（取り込みで減らさない）。取得日は、同じ内容のものは引き継ぎ、新しい・変わったものだけ `--fetched` の日時にする
- 取り込み結果: 735件・281市区町村（電話あり695、住所あり…。電話が問い合わせ先のもの231、Web補完71）

## 施設名を直したCSV（2026-10-20）
`grandgolf_facilities_formal_names.csv`（統合CSVに「施設名（元）」「施設名」「名称確認」「名称確認根拠」の列が増えたもの）。`施設名` の列を使う。同じコマンド（`--enriched`）で取り込む。

- 名前を直した27行（「施設」「グラウンド」「多目的広場」「施設写真」など、名前になっていなかったもの）が、載せられる名前になった。根拠は、各市区町村のページ（`名称確認根拠`）
- **名前を直した行は、直す前の名前で載せていた施設を置き換える**（`original_name`。古い名前を残さない）

## 県ページの見せ方と地図（2026-11-09 に作り直し）
- 「施設を探す」節（`MunicipalPlaces.astro`）は、本文用の余白・リスト記号の設定（`.prose-article`）の外に置く。中に置くと、リストが字下げされ、段落の余白が広がる。
- 構成: 要点2行＋くわしい注意（折りたたみ）→ 県の地図と凡例 → 市区町村の目次（ボタン。タップでその市区町村の最初の項目へ。折りたたみの中なら開く）→ 絞り込み（件数・該当なし・クリア・「住所・電話番号のある施設だけ」）→ ①住所・電話番号が載っていた施設（カード。個別に調べた施設 `osm-course-examples.ts` もここに合流）②住所・電話番号が載っていない施設（1行）③施設名が載っていない案内ページ（市区町村ごとに1行）。①②③とも、先頭だけ見せて「ほかの◯件を見る」にたたむ。
- データを組み立てるのは `src/data/places-view.ts`。個別に調べた施設の市区町村は、住所の先頭から判定する。
- 地図（`PrefMap.astro`）は補助。濃い緑＝住所・電話番号のある施設がある、斜線＝市区町村の案内に記載がある、灰色＝調べられていない・記載を確認できなかった。色だけに頼らず、模様と、広い市区町村の件数の数字を付ける。タップで目次と同じ場所へ移る。キーボード・読み上げは目次で行う。
- 形のデータ: `src/data/pref-maps/<slug>.json`。作り方は `scripts/maps/build-pref-maps.mjs`（`npm run maps:build -- <TopoJSON>`）。元は、国土交通省 国土数値情報（行政区域データ）2021年版を、スマートニュース メディア研究所が簡素化した `N03-21_210101_designated_city.json`（https://github.com/smartnews-smri/japan-topography。政令指定都市の区は市に結合済み）。本土（いちばん面積の大きい、25km以内でつながる陸地のまとまり）だけを描き、離れた島だけの市区町村は「離島など」のタイルにする。座標は間引いてあり、境界は正確ではない。出典の表記は、図の直下と `/about/#places`。
- 市区町村の合併・再編で、施設データの市区町村コードが地図の元データ（2021年版）にないと、図に出ない。その場合は元データを新しい版に替えて、`npm run maps:build` をやり直す。


## 市区町村の五十音順（読み仮名）
県ページの「市区町村から探す」は、市区町村が8以上のとき、五十音の行（あ行・か行…）ごとに並べる。読み仮名は総務省「全国地方公共団体コード」（令和6年1月1日現在）から作った。

- データ: `data/places/municipality-readings.json`（団体コードの先頭5桁 → ひらがな。政令指定都市の区・東京23区を含む。約1,900件）
- 作り方: 元のExcelを `https://www.soumu.go.jp/main_content/000925835.xlsx` から取り、リポジトリの外に置いて `python3 -I scripts/places/build-readings.py code.xlsx data/places/municipality-readings.json`（標準ライブラリだけで動く）
- 使う所: `src/data/municipality-readings.ts`（行の判定）、`MunicipalPlaces.astro`（並べ替え・見出し）。読み仮名が無い団体は、名前の順で最後に置く（総務省の表に無い団体コードのとき）
- 出典の表記: 該当の節の下に「市区町村の読み仮名：総務省『全国地方公共団体コード』による。」
- 市区町村の合併・名称変更があったら、新しい表で作り直す（地図データの更新と合わせる）


## 週ごとの取り直し（2026-11-11〜。置き換えず、足す）
運営者が週ごとに取り直す「施設の詳細CSV」（列: prefecture, municipality_code, municipality_name, facility_name, address, phone, inquiry_dept, inquiry_phone, page_title, page_url, multi_facility, keyword_in_item, matched_text, …。`extract_route` が `weekly_…`）を、いま載せているデータに足す。
```
node scripts/places/check-https.mjs <今週のCSV>
node scripts/places/weekly-update.mjs <今週のCSV> --surveyed=<取得日> --review-dir=<確認用ファイルを置く場所>
npm run build
```
- 新しい元ページ（places.json にないURL）は `clean-places.mjs --append` で足す。住所・電話番号（details.json）は、施設の項目にグラウンドゴルフの語がある行（`keyword_in_item=1`）か、1施設だけのページの行だけを使う（複数施設を並べたページの、語のない施設に「グラウンドゴルフあり」と誤って付けないため）
- すでにある施設は、住所か電話番号が空だったときだけ埋める。値が食い違うものは、いまの値を残して、確認用の `details-skipped-and-conflicts.json` に出す
- イベント・記事の題名らしい名前、付帯施設、使用料などの名前は足さない（その一覧も同じファイル）
- 今週のCSVに無いものは残す。同じCSVをもう一度流しても結果は変わらない
- **やってはいけないこと**: 週のCSVで、details.json を作り直さない（住所・電話番号を補ってあるデータが、取り直しの粗いデータに置き換わってしまう。実際に、直接作り直すと、郡山市のスポーツ広場の住所が消えた）
- 実績（2026-11-11のCSV、1,405行）: 新しい元ページ100件のうち、追加45件（施設・一覧ページ）、新しい市区町村8（宮城県角田市、新潟県小千谷市、群馬県渋川市、福岡県大木町、京都府京丹波町、岐阜県川辺町、鹿児島県大崎町・宇検村）。住所・電話番号は、新しい施設20件を追加し、空欄1件を補った。足さなかった5件（イベントや記事の題名など）。http のページ28件のうち25件は https で開けた


## 2回目の取り直し（2026-11-16に受け取った11ファイル）の扱い
運営者が地方自治体の1次情報から、11ファイル（places・places_1・others・others_1・places_detail_1・events・events_1・events_detail_1・pages・pages_1・pdfs）を取り直した（取得は2026-11-14）。使えた形と使わなかった形:
- **使った**: `grandgolf_places.csv`・`grandgolf_places_1.csv`（調査の形。`page_kind=facility` の行だけ。元ページが https のものだけ、http は `check-https.mjs` で開けたものだけ）→ `clean-places.mjs --append`、`grandgolf_places_detail_1.csv`（詳細の形）→ `weekly-update.mjs`、`grandgolf_events_detail_1.csv`（イベントの詳細）→ `clean-municipal.mjs --merge`
- **使わなかった**:
  - `others`・`others_1`（`page_kind=other` と `organization`。施設の案内ではない。団体・クラブの紹介ページなど）。足すと「施設の案内ページ」の一覧に、同窓会やシルバー人材センターなどが入ってしまうため
  - `events`・`events_1`（イベントのページの一覧で、日付などの詳細は `events_detail` にある）

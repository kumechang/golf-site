# 都道府県別の予定表（市区町村の大会・教室）

`/community/events/<県>/` に出す予定表。運営者が市区町村の公式サイトから集めたCSVを、載せてよい項目だけに整理して使う。
協会の大会カレンダー（`/community/events/`、`data/events/approved.json`。運営者が1件ずつ確認して承認）とは、集め方が違う。県ページには両方を、重複をまとめて載せる。

## 更新の手順
1. 運営者から、イベントのCSV（列: prefecture, municipality_code, municipality_name, event_name, event_kind, date_text, date_basis, date_start, date_end, venue, organizer, target, fee, deadline, contact_dept, contact_phone, evidence, page_url, extracted_at など）を受け取る。**CSVはリポジトリに入れない**（市区町村のページの文字を含むため。`docs/places/README.md` と同じ扱い）。
2. 元ページが http のものがあれば、先に `node scripts/events/check-https.mjs <CSV>...` で、https で開けるかを確かめる（開けたものだけ `data/events/https-upgrades.json` に残る。TLS検証は外さず、1.5秒おきに1件ずつ取得する）。
3. `node scripts/events/clean-municipal.mjs <CSV>... --review=<確認用CSV>` で `data/events/municipal.json` を作り直す。標準出力に、残した件数と、除いた理由の内訳が出る。確認用CSVに、除いたものの一覧（理由つき）が出る。
4. `npm run build` と `npm run test:crawler`。
5. 県ごとの件数・noindex の様子を確認してから、PR。

## 通す条件（`scripts/events/municipal-lib.mjs`）
- 元ページが https（http のものは、https で開けると確かめたものに置き換える）。市区町村コードがある。
- 名前に「グラウンドゴルフ」がある（専用の大会）、または複数競技の大会で、根拠の文にグラウンドゴルフがある（「複数競技の大会（グラウンドゴルフを含む）」と表示）。選定・ネーミングライツ・結団式・結果の記録集などは除く。
- 日付は、日付の文章に開催日の月日が書かれているものだけ。本文からの推定は、日付が1つに決まるものだけ。確かでなければ「日程は元のページで」に回す。結果ページの投稿日を開催日と取り違えないよう、名前の年度と合わないものは除く。
- 開催が10日を超える期間は「期間のある催し」として、開催日は元のページで確認と表示する。
- 会場・主催・参加費・対象・申込期限・問い合わせ先は、短く整えられたものだけ。主催は団体名らしいものだけ（個人名らしいものは除く）。電話は、課名が確かなときだけ載せる。
- 延期になった大会は、元の日付が当てにならないので日付なしにする（元の日付が古ければ除く）。「更新日」が開催日として読まれたものも日付なしにする。
- 同じ大会の重複（結果ページと募集ページなど）は、項目の多いほうにまとめる。日付なしは、同じ大会の日付ありがあれば除く。

## 運営者の判断で載せないもの
`data/events/municipal-overrides.json` の `exclude` に、`municipal.json` の id と理由を書く。clean-municipal.mjs が読み、確認用CSVにも理由つきで出る（再生成しても消えない）。

## ページの出し方（`src/data/pref-events-core.mjs`）
- 分類は、ビルド日（日本時間）を基準に、今後／日程は元のページで／終了（直近12か月）。JSは「これからの予定」で過ぎたものに「終了」の文字を出すだけ。
- ページは、予定が1件でもある県に作る（データがない県は作らず、ハブに「掲載なし」）。
- 検索に載せる（index）のは、日付の分かる予定が5件以上（終了分を含む）かつ2市区町村以上で、今後の予定がある（または直近180日に開催があった）県だけ。それ以外は `noindex,follow` で、サイトマップにも入れない。しきい値は仮説で、`pref-events-core.mjs` の定数。Search Console で見直す。
- sitemap の lastmod は、その県の予定を読み取った日のうち最も新しいもの。
- 表示の「読み取った日」は、今後・日程不明の予定のうち最も古い読み取り日。90日を超えるとビルドに警告が出る。
- Event の構造化データ（JSON-LD）は付けない。掲載元と主催が違う、会場の欠けが多い、中止・延期を静的サイトで検知できない、が理由。付ける場合の条件は `docs/handover/briefs/pref-events-seo.md`。

## 運営者の確認（2026-11-04）
- 集めたデータは、すべて地方自治体の一次情報から。robots.txt は集めるときに確認済み。すべて掲載してよい、との確認を受けた（`/about/#municipal-events` に記載）。
- 元ページが http だった予定は、https で開けるものを足した（候補11件がすべて開けた）。

## 注意
- 自動の整理なので、誤りが残る。気づいた点は、確認用CSVとあわせて知らせてもらえれば、ルールを直す。


## 週ごとの取り直し（2026-11-11〜。置き換えず、足す）
運営者が週ごとに取り直すCSV（列は同じ。`events_route` が `weekly_…`）を、いま載せているデータに足す。
```
node scripts/events/check-https.mjs <今週のCSV>
node scripts/events/clean-municipal.mjs <今週のCSV> --merge --review=<確認用CSV>
npm run build && npm run test:crawler
```
- `--merge`: 今週のCSVにあるものは、新しい内容・読み取り日に置き換え、今週のCSVに無いものは**残す**（消えたのか、取れなかっただけなのか分からないため。開催日が過ぎたものは、ページの分類が自然に「終了」へ移す）。同じCSVをもう一度流しても結果は変わらない
- 実績（2026-11-11のCSV、816行）: 載せる条件を満たしたのは163件。いまの176件と比べて、新しい7件（土岐市・静岡市・山形市・出水市・玉野市・喜界町）、内容が変わったもの0件、今週のCSVに無く残したもの20件。結果として県ページが2つ増えた（岐阜県・山形県）
- 内容が変わったかは、名前・日付・会場・主催・対象・参加費・申込期限・問い合わせ先・中止・延期・元ページで見る（`--merge` の表示に件数が出る）

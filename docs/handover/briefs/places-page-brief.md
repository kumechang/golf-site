# 設計ブリーフ: 市区町村の案内に「グラウンドゴルフ」の記載がある施設

作成日 2026-10-18 / 対象: data/places/places.json（flags 空のみ）/ 実装はしない

## 0. 結論(推奨)

1. **新ページは作らず、既存の都道府県ページ(47)に新しい節を1つ足す**。`#municipal-places`。並びは「協会の窓口 → JGGA認定コース → **市区町村の案内に記載がある施設(新)** → 地図データの例(OSM) → あわせて読みたい」。
2. 市区町村ごとにまとめる。合計20件以上の県は市区町村ごとに `<details>`(2件以下の市区町村は開いたまま)。20件未満は折りたたまない。
3. 1件は「施設名(太字)＋市区町村の案内ページへのリンク」。施設名なしの一覧ページは「◯◯市の施設の案内ページ(グラウンドゴルフの記載あり)」。取得日は節の先頭に1回だけ。
4. 「利用できる」とは書かない。**載っていない市区町村=未確認**を節の先頭の箇条書きで明記。
5. 構造化データなし、title変更なし、description に一文だけ足す。sitemap 変更なし。
6. **公開前に必ず直す2点(データの実態から判明)**: (a) 施設名にリンク文字列の混入が約60件ある(§4.2)。(b) http:// のURLが34件ある(§4.3)。運営者の「印付きは載せない」だけでは足りない。

### 1.2 OSM の節との関係
- 情報源が違う(市区町村の案内へのリンク / 地図データの住所・電話)。**統合も重複排除もしない**。同じ施設が両方に出ても、出典が別という説明で足りる。
- 見出しで区別する。新: 「{県}の市区町村の案内に、グラウンドゴルフの記載がある施設」。既存OSM: 「{県}で地図データから確認できる施設の例」(変更しない)。
- 新節を先にする理由: 件数が多く、出典がそのまま市区町村のページで、読者が次に取る行動(問い合わせ)に近い。OSM節の導入文「JGGA認定コースとは別の情報源」はそのまま使える。
- 節の書き出しに1文: 「JGGA認定コースとは別に、市区町村が公開している案内を調べたものです。」(「認定」は協会の制度名として区別のためだけに使う)

### 1.3 件数が多い県の読みやすさ(静的)
- 見出し階層: h1(県) > h2(この節) > h3(市区町村)。施設は `<ul>` の `<li>`(`role="list"` を付ける。既存ページと同じ)。
- 合計20件以上の県(23県)は、市区町村ごとに `<details><summary><h3>◯◯市(12件)</h3></summary>…</details>`。summary 自体が目次になる(愛知26市町、埼玉26、東京22、群馬20…)。閉じた状態で並べば26行。JSなしで動く。
- 開閉の初期状態: 市区町村の件数が2以下なら `open`、3以上は閉じる。
- 20件未満の県(24県)は全部開いたまま、h3＋リスト。
- ページ内検索・絞り込みJSは作らない(ブラウザの検索で足りる。details内はChrome/Firefox/Safariの検索で自動で開く)。
- 1市区町村の最大は21件(霧島市)。それでも details 内で一画面に収まる範囲。
- 節の先頭に件数を出す: 「{N}市区町村・{M}件」。ランキングに見えないよう、親ページには県別の件数を載せない。

### 1.4 件数ゼロの県
現データでは **47都道府県すべて1件以上**(少ない順: 北海道1、富山1、徳島2、高知3、香川4)。ただし将来の再調査でゼロになりうるため、コンポーネントはゼロ件分岐を持つ:「調べた範囲では、{県}内の市区町村の案内にグラウンドゴルフの記載を確認できていません({日付}時点)。ない、という意味ではありません。…」＋協会窓口への案内。節ごと消さない(JGGA認定コースのゼロ分岐と同じ作り)。
少ない県(合計3件以下)には1文足す: 「{県}は、調べた範囲で記載を確認できたのが{n}市区町村にとどまります。実情の差とは限りません。」

## 3. 文言案(実文)

### 3.1 節(県ページ)
h2: `{県}の市区町村の案内に、グラウンドゴルフの記載がある施設`

導入:
> {県}内の市区町村が公開している、施設の案内ページのうち、グラウンドゴルフの記載があったものへのリンクをまとめました。{N}市区町村・{M}件です。<time>{2026年10月17日〜18日}</time>に、運営者が各市区町村のページで確認したもので、その後に変わっていることがあります。

h3(または `<p class="font-bold">`) 「ご覧になる前に」＋箇条書き:
- 全国の市区町村をそろえて調べたものではありません。載っていない市区町村は、調べられていないか、記載を確認できなかったところです。施設がない、グラウンドゴルフができない、という意味ではありません。
- 確認できたのは、「市区町村の案内に、グラウンドゴルフの記載がある」ところまでです。いま利用できるか、誰でも使えるかは、確認できていません。
- 予約が要るか、料金、使える方(その市区町村の方だけ、団体のみ、個人は不可など)、休業や工事は、施設ごとに違います。出かける前に、市区町村の担当窓口か施設に確認してください。
- 件数の多い少ないは、各地の実情ではなく、調べられた範囲の違いによることがあります。
- 施設名は、市区町村のページに載っていた呼び名です。施設名がないものは、その市区町村の施設の案内ページへのリンクです。どの施設に記載があるかは、リンク先でご覧ください。
- ページの本文は転載していません。くわしくは、各リンク先をご覧ください。

節末(`not-prose` の外の通常段落):
> お住まいの市区町村が載っていない場合は、市区町村のスポーツ振興課や社会福祉協議会に、グラウンドゴルフができる場所を尋ねてみてください。上の「{県}グラウンド・ゴルフ協会の窓口」も手がかりになります。
> 当サイトは、市区町村とは関係のない個人運営の情報サイトです。この一覧は、各市区町村が作ったものではありません。掲載内容に誤りがある場合や、掲載を望まれない場合は、<a href="/about/">サイトについて／運営者情報</a>のお問い合わせ先までご連絡ください。内容を確認のうえ、対応します。調べ方は<a href="/about/#places">こちら</a>です。

### 3.2 description(県ページ)
現行を維持し、記載のある県(現在は全県)にだけ追記:
> {県}でグラウンドゴルフのクラブやコースを探している方向けに、都道府県協会の窓口情報と、JGGA(日本グラウンド・ゴルフ協会)認定コースの情報に加え、市区町村の案内にグラウンドゴルフの記載がある施設へのリンクをご紹介します。

### 3.3 /about/ に足す節(`#places`、`#crawler` の直後)
h2 id="places": 「市区町村の施設の案内について」
> 各都道府県のページの「市区町村の案内に、グラウンドゴルフの記載がある施設」は、市区町村が公開している施設の案内ページを調べて、グラウンドゴルフの記載があったものを集めたものです。調べたのは2026年10月17日〜18日です。
- 調べ方: 各サイトのrobots.txtと利用規約を、運営者が取得の際に確認しました。取得が認められていないものは、対象にしていません。
- 保存・掲載する情報: 市区町村名、施設名、元のページのURL、確認日だけです。ページの本文や画像は、保存も掲載もしていません。個人の氏名や連絡先は扱っていません。
- 公開前の確認: 記載の意味が不確かなものなど、運営者が確認の印を付けたものは載せていません。
- 範囲: 全国の市区町村をそろえたものではありません。
- ご連絡: 掲載内容の訂正、掲載の取り下げを希望される場合は、下記のお問い合わせ先までご連絡ください。内容を確認のうえ、対応します。

`#crawler` との整合(**要運営者確認**): #crawler は「大会カレンダー」用で、UA `GroundGolfNaviBot/1.0` を名乗る。今回の調査が同じクローラーで行われたのか別の方法かをブリーフ作成側では確認できていない。**実際の方法に合わせて書く**。同じなら #crawler の目的・保存項目に「施設の案内ページ(施設名・市区町村名・URL)」を追加。別なら #places に「大会カレンダー用のクローラー(上記)とは別に調べました」と書き、UA の記述を流用しない。「取得時に確認した」は運営者が確認済みという事実を書くだけにとどめ、「規約上問題ない」「許可を得た」とは書かない。

## 4. データの扱い

### 4.1 読み込みと検証(`src/data/places.ts`、events.ts と同じ手書き検証。依存追加なし)
- `data/places/places.json` を import。許可リスト方式で項目を取り出す(スキーマ外の項目は読まない)。
- 不正はビルド失敗(`[places] {source_url}: …`):
  - kind が facility/listing 以外。facility で name が空、listing で name が非null。
  - prefecture が prefectures.ts の name に無い。municipality_code が `/^\d{5}$/` でない、または先頭2桁が県と合わない(prefectures に JIS 番号が無ければ配列順=JIS順を確認して index+1 を使う)。
  - source_url が `new URL()` で解釈できない、**protocol が https: でない**、ユーザー情報(user:pass@)を含む。
  - 同一 (municipality_code, name) の facility、同一 source_url の重複。(現データは0件)
  - surveyed_at が不正。
  - 施設名の lint(§4.2)に引っかかる。
- `flags.length > 0` は黙って除外(エラーにしない)。ログに除外件数だけ出す。
- `prefecture` と `slug` の対応は prefectures.ts の name で引く。全県が1回は引けること(未知の県名は失敗)。

### 4.2 施設名の混入(実データで確認。要対応)
flags 空の施設754件のうち、リンク文字列の混入らしき名前が**約60件**ある。例:
- 日付・メモ付き: 「丸山スポーツ広場 [2021年4月23日]」「多目的スポーツ広場 2024-01-15」「菊池市営グラウンド」の前に日付。
- UI文字: 「丸山スポーツ広場 (別ウインドウで開く)」「📎 多目的芝生広場」。
- 手続き・案内ページ名: 「公園の利用申請」「公園利用のルールとマナー」「赤坂総合公園グラウンド・ゴルフ場使用許可申請書」「杣川運動公園のページへ」「瀬戸町総合運動公園体育館の詳細ページはこちら」。
- 文で終わる: 「名神高速道路高架下多目的広場が利用できます」「美甘グラウンドをご利用ください」(**「利用できます」を当サイトが言う形になるので不可**)。
- 担当課名: 「…(デジタル・みらい戦略課)」。
- 長文・複数施設: 38件が26字以上(「…使用券購入」「コース独占使用」で切れた例あり)。

対応:
1. **`data/places/overrides.json` を新設**(source_url をキーに `{exclude:true}` / `{name:"直した名前"}` / `{asListing:true}` = 施設名を捨てて一覧ページ扱いに降格)。places.json は再生成で上書きされるので、人の判断は別ファイルに残す。
2. places.ts が overrides を適用後に lint。lint は失敗(エラー)にする: 絵文字、`/\d{4}[-\/年]\d{1,2}|令和\d|平成\d/`、`別ウィンドウ|別ウインドウ|PDF|ページへ|詳細ページ`、`できます|ください|申請|申込|お知らせ|ルール|マナー|について`、全角/半角括弧内の課・係・室、40字超。警告(ビルドは通す): 26字超、名前が5字以下で一般的な語のみ(「総合公園」「各広場」「公園愛護会」)。
3. 公開前に運営者(または担当役)が、lint の結果＋施設名全件をCSVで一度通読し、overrides を埋める。迷うものは `asListing`(降格)が安全側。
4. 「公園愛護会」「各広場」のような施設名でないものも降格か除外。

### 4.3 http:// のURL(34件)
現データの34件(秋田・山形・群馬・埼玉・千葉・長野・静岡・京都・大阪・兵庫・和歌山・鳥取・岡山・福岡・鹿児島、施設名ありは約22件)が http://。要件「https のみ」を守ると表示されなくなる。
- 推奨: 再調査の際に、運営者が https 版が同じパスで開くかを確認し、開けば https に直して places.json を作る。開かないものは載せない(確認用CSVに「除外: http」と出す)。
- `lib.mjs` 側の変更案(実装時): http は除外理由 `http` で excluded に回す(places.json に入れない)。ビルド時の検証は §4.1 のとおり失敗にする。
- 暫定で http を載せる案は非推奨(混在コンテンツ警告、`rel=noopener` でも http への遷移で閲覧者に警告が出る端末あり、シニアには不安材料)。

### 4.4 並び・重複
- 市区町村は `municipality_code` 昇順(JIS順)。同一コード内は places.json の記載順(安定)。五十音ソートはしない。
- 同名施設は別の市区町村なら別物として両方載せる(重複排除しない)。同一市区町村の同名は失敗(§4.1)。
- 市区町村名は places.json の値をそのまま見出しにする(政令市の区は現状7件。区は市の下にまとめず、そのまま別見出し)。

### 4.5 更新手順(`docs/places/README.md` に書く。実装時)
```
npm run places:clean -- <再調査CSV> --review=<確認用CSV>   # package.json に追加。中身は node scripts/places/clean-places.mjs
 → data/places/places.json を更新(印付き・http・除外理由は確認用CSVに出る)
 → 確認用CSVと施設名の通読 → data/places/overrides.json を更新
npm run build    # 検証・lint が通ること
```
→ 通常の変更手順(コミット→push→PR→squash)。取り下げ依頼が来たら、overrides に `exclude` を足して当日中に反映する(places.json は触らない)。surveyed_at は調査日なので、一部だけ再調査したときは「県ページの取得日=その県の最古〜最新」で出る。ビルド時、最古の取得日から180日以上で `console.warn`(events.ts と同様)。

## 5. SEO

## 6. アクセシビリティと実装方針
- 見出し: h1 > h2(節) > h3(市区町村)。節の注意書き(「ご覧になる前に」)は見出しにせず、太字の段落＋箇条書きにして、h3 を市区町村だけに使う(読み上げの見出し一覧が市区町村の目次になる)。節全体は `<section aria-labelledby>` で囲む。
- `<details>`: `<summary>` は `min-h-[44px]`・フォーカスリング(`focus-visible:outline`)・開閉の三角を可視で残す(既定の marker を消さない)。summary 内に h3 を入れる(HTML仕様で可)。summary の文字は「◯◯市(12件)」。ネストしない。
- リスト: `<ul role="list">`。リンクは可視の文字＋sr-only の施設名(リンク名の一意性)。「こちら」「詳細」だけのリンクは作らない。
- コントラスト: 本文 `text-slate-700` 以上、リンク `text-green-800`。補助文字に `text-slate-400/500` を使わない(OSM節の出典の `text-slate-400` は現状コントラスト不足なので真似しない)。
- 375px: 1カラム、`min-w-0 break-words`(長い施設名は40字まで折り返す)、横スクロールなし、リンクに `tap-target`(既存クラス)。
- 色だけに頼らない: 件数やラベルは文字で示す。
- 構成案:
  - `src/data/places.ts`: 読み込み・検証・overrides 適用・lint・`getPlacesBySlug(slug)`(戻り値: `{ total, municipalityCount, from, to, groups:[{code,name,facilities[],listings[]}] }`)。
  - `src/components/MunicipalPlaces.astro`: 県名と `getPlacesBySlug` の結果を受けて節全体を描画(ゼロ件分岐・少数分岐・details しきい値を内包)。[prefecture].astro は `<MunicipalPlaces pref={pref} />` を1行足し、description を更新するだけ。
  - 取得日の整形は events.ts の `jstDate` を再利用。

## 7. コンプライアンス
- 載せるのは自治体名・施設名・出典リンク・取得日の事実だけ。本文・画像・住所・電話・営業時間は載せない(個人情報なし。担当課名や担当者名が混ざった名前は§4.2で除く)。
- 使わない語: 「公式」(自治体のページは「市区町村の案内(ページ)」と書く)、「提供」(自治体が情報提供している、のように)、「認定」(JGGA認定コースとの区別でのみ可)、「利用できます/使えます/プレーできます」、「おすすめ」「穴場」「スポット」「施設一覧」(網羅の含み。「リンクをまとめました」と書く)、「全国の」。
- 出典リンクは全件に付ける。「掲載元」と「主催者」の区別: ここでは掲載元=市区町村のページで、施設の運営者とは限らない。必要なら節に「リンク先は市区町村のページで、施設の運営者のページとは限りません」を足す。
- 当サイトが市区町村とは無関係の個人運営であることを節末に明記(§3.1)。訂正・削除の連絡先は /about/ の contact@ground-golf-navi.com。
- 自治体の文章の転載なし(施設名は呼称であり、本文の抜粋ではない)。

# イベント情報の確認（公開までの流れ）

クローラーが集めたイベントは、**人が承認したものだけ**を公開用の一覧にする。承認の記録はリポジトリに残し、取得し直しても判断が引き継がれる。

```
crawl:events ──▶ events.json（取得した全件。コミットしない）
                      │
review:events report ─┴─▶ review.md（要判断・重複の疑い・承認済み・見つからない判断）
                      │
review:events decide ───▶ data/crawler/review/decisions.json（判断の記録。コミットする）
                      │
review:events build ────▶ data/events/approved.json（承認済みの公開用一覧。コミットする）
```

## 手順

```bash
npm run crawl:events                                   # 1. 取得（今日以降の開催予定が「公開候補」になる）
npm run review:events                                  # 2. レポートを作る（最新の出力を使う）
npm run review:events -- decide E-8b9368f4 approve "メモ"        # 3. 承認
npm run review:events -- decide E-ed79f86f dup:E-8b9368f4 "表記違い"  #    同じ大会は統合先を指定
npm run review:events -- decide E-edb198c7 reject "県不明のため保留"   #    却下
npm run review:events -- build                         # 4. 承認済みを data/events/approved.json に書く
```

試すときは `--decisions=<path> --approved=<path>` で保存先を変えられる。`--in=<出力ディレクトリ>` で使う出力を指定できる。

## 判断の基準

承認する前に、元ページ（`source_url`）を開いて次を確かめる。

1. **開催日・大会名・会場が元ページと合っている**（レポートの「注意」を必ず読む）
2. **一般の人が参加できる大会か**（団体・企業の利用枠、会員向けの活動は却下）
3. **開催地の県が分かる**（「開催地の県が不明」は、元ページで確認できるまで承認しない）
4. **非公式の情報源**（「非公式の情報源」の印）は、公式の確認が取れるまで承認しない
5. **参加できる人が限られていないか**。取得できる情報には「参加資格」がない。名前に「指導員」「優良プレーヤー」「選考会」「予選会」などがあるもの（「参加対象が限られる可能性」の印）や、研修・講習は、元ページで一般の人が参加できると確認できるまで承認しない。**公開するときは、全イベントに「参加資格・申込は主催者の案内で確認してください」と表示する**（協会の月例大会・県民スポーツ大会などは会員や市町の代表だけが参加する場合がある）
6. **大会名の括弧書きの日付**（例「(7/31)」）は、実施日ではなく予備日・別日のことが多い（神戸市の例：表の日付どおりに開催されていた）。表の日付を採り、括弧の日付は元ページで確認する
7. **申込締切を過ぎている**ものは、公開時に「申込受付終了」と分かる表示にする（今は印だけ）
8. **重複**：「同じ大会の可能性が高い」は、情報の新しい・詳しい方を承認し、もう一方は `dup:` で統合する。「日程だけ同じ」は別の大会のことが多い

## 仕組みの決まり

- **id**（`E-xxxxxxxx`）は「都道府県＋開始日＋大会名＋情報源」から決まる。**日程や名前が変わると id が変わり、承認が外れて再確認になる**（古い判断はレポートの「見つからなかった判断」に出る）
- 承認済みでも、**開催日を過ぎると公開用の一覧から外れる**
- 公開用の一覧には、本文・画像は入れない（大会名・日程・開催地・会場・申込締切・元ページURL・掲載元など）。`listed_by` は掲載元の団体で、大会の主催者ではない
- クローラーが取得しない情報源（台帳で `allowed` 以外）のイベントは、そもそも一覧に入らない

## 承認するとき：区分（level）と補足

承認には `--level` が必須（付け忘れると `decide` も `build` も止まる）。

```
npm run review:events -- decide <id> approve "内部メモ" --level=local|block|national
```

- `local`：県のセクションに出る　/　`block`・`national`：「全国・ブロック大会」の別枠に出る（開催地が他県でも県のセクションには入れない）
- 任意：`--organizer=`（要項などで主催者を確認できたときだけ。あると「主催」行が出る）、`--display-name=`（表記ゆれを直すとき）、`--public-note=`（読者向けの補足。事実だけ・1文・個人名や連絡先は入れない）
- 内部メモ（`note`）は公開ページには出ない。読者向けの補足は `public_note`
- 承認を再実行しても、前に付けた区分・主催者・表示名・補足は、新しく指定しない限り引き継ぐ

## 公開ページ

`/community/events/`（`src/pages/community/events/index.astro`）が `data/events/approved.json` を読む。開催日を過ぎた大会はビルド時に外れ、ブラウザ側でも隠す。ビルドの「今日」を変えて表示を試すには `EVENTS_TODAY=2026-10-16 npm run build`（本番ビルドには付けない）。
